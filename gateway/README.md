# dbcp-api-gateway

## Описание

Данный репозиторий содержит API Gateway, являющийся частью курсового проекта по дисциплине «Проектирование и разработка баз данных» в рамках образовательной программы подготовки бакалавров по направлению 09.03.04 — Программная инженерия.

API Gateway реализован на языке Go (Golang) и предназначен для связи frontend‑приложения с backend‑сервисом, реализованным на gRPC. Gateway предоставляет HTTP/REST‑интерфейс и выполняет роль адаптера между HTTP‑клиентами и gRPC‑сервисами основного backend‑проекта.

Проект также является частью моего портфолио Golang‑разработчика и демонстрирует практическое применение gRPC в сочетании с HTTP‑API, роутингом и middleware.

## Назначение API Gateway

API Gateway решает следующие задачи:

* предоставляет HTTP‑интерфейс для frontend‑приложений
* инкапсулирует gRPC‑клиенты и protobuf‑контракты
* преобразует HTTP‑запросы в gRPC‑вызовы
* централизует CORS, логирование и тайминги запросов
* упрощает интеграцию frontend‑части с backend‑сервисом

## Технологический стек

* Go (Golang)
* net/http
* gRPC (client)
* Protocol Buffers
* chi router
* CORS middleware
* slog (structured logging)
* YAML‑конфигурация
* Makefile

## Связь с основным сервисом

Gateway взаимодействует с gRPC‑сервисом проекта `database-course-project`, который отвечает за бизнес‑логику и работу с базой данных PostgreSQL. Все CRUD‑операции и отчетные запросы проксируются через gRPC‑клиенты.

## Архитектура

* HTTP‑сервер принимает REST‑запросы от клиентов
* Каждый HTTP‑handler соответствует отдельной бизнес‑сущности
* Для каждой сущности используется собственный gRPC‑client
* Конфигурация сервиса загружается из YAML‑файла
* Логирование адаптировано под окружение (local / dev / prod)

Проект следует принципу разделения ответственности между HTTP‑слоем и транспортным gRPC‑слоем.

## HTTP API

Gateway предоставляет REST‑эндпоинты для следующих сущностей:

* `/vessel` — суда
* `/cargotype` — типы грузов
* `/cargo` — грузы
* `/operation` — операции
* `/opercargo` — связь операций и грузов
* `/storageloc` — места хранения
* `/report-cargo-detail` — детальный отчет по грузам
* `/report-cargo-type` — отчет по типам грузов

Каждый эндпоинт транслируется в соответствующий gRPC‑метод backend‑сервиса.

## Структура проекта (обобщенно)

* `cmd/` — точка входа в приложение
* `internal/` — HTTP‑handlers, конфигурация, логирование
* `protos/` — сгенерированные protobuf/gRPC клиенты
* `config/` — конфигурационные файлы
* `Makefile` — команды запуска

## Конфигурация

Для запуска используется переменная окружения `CONFIG_PATH`, указывающая на YAML‑конфигурацию.

Пример `local.yaml`:

```yaml
env: "local"
http_server:
  address: "localhost:8081"
  timeout: 4s
  idle_timeout: 60s
grpc:
  address: "localhost:44044"
  timeout: 5s
```

## Makefile

Доступные команды:

* `make run` — запуск API Gateway

## Запуск проекта локально

1. Убедиться, что запущен gRPC‑backend (`database-course-project`)
2. Создать файл `.env`:

```
CONFIG_PATH=config/local.yaml
```

3. Запустить API Gateway:

```
make run
```

После запуска HTTP‑сервер будет доступен по адресу, указанному в конфигурации.

## Назначение проекта
